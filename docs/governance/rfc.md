# Quy trình RFC

## Khi cần RFC

Thay đổi public API, token schema, kiến trúc package, framework mục tiêu, browser support, license, quyền đóng góp hoặc chính sách tương thích cần RFC trước khi triển khai lớn.

## Nội dung

1. Tóm tắt và trạng thái (Draft, Review, Accepted, Rejected, Superseded).
2. Vấn đề, người dùng bị ảnh hưởng và mục tiêu không làm.
3. Đề xuất, lựa chọn thay thế và đánh đổi.
4. API/kiến trúc, migration, accessibility, bảo mật và quyền sở hữu trí tuệ.
5. Kế hoạch triển khai, kiểm thử, rollout và owner.

RFC cần thời hạn review công khai hợp lý; maintainer ghi quyết định và lý do. RFC được chấp thuận không thay thế review code.
